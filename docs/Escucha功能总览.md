# Escucha 功能总览（线上 v8，2026-10-27）

> 读者：AI-Brain 审查者 + 用户。依据：当前代码（`server.py`、`assist.py`、`static/*`）和 `docs/功能清单.md`。
> 本文**不含**任何密钥、Key、访问码的值。

---

## 1. 定位与痛点

- **一句话**：面对面对话的实时翻译助手。人在国外看医生、去学校、去银行、办政府手续，听不懂对方的语言时用它。默认是中文⇄西班牙语，可以换成任意两种语言。
- **痛点**：市面上的翻译 App 在**朗读译文时会停止收听**。对方一插话，那几句就漏了，用户只能打断对方、重来。
- **第一卖点：全双工（同时说、同时听）**。麦克风从头到尾不关；朗读时对方插话照样识别、翻译、显示，朗读声音会自动变小。
- **第二卖点：不只翻译，还帮你把事办完**。它会自动判断场合，记下已经说清的信息，建议你怎么回，提醒你还没问的重要问题，最后生成纪要、待办和日历。
- **比赛**：Meta 黑客松 Indie 赛道，**11 月 4 日前提交**（截止 2026-11-05 03:00 马德里时间）。
  - 评分：Impact 30% / Meta tooling 25% / Demo 25% / 技术深度 20%。
  - 规则允许用第三方工具。
- **部署地址**：自行部署后的 `https://your-domain.example/`（本地运行为 `http://localhost:8765`）。

## 2. 架构

```
iPhone/浏览器页面 (static/)
  ├─ 麦克风 getUserMedia（回声消除/降噪/自动增益）→ AudioWorklet → PCM16 24kHz 单声道，每 80ms 一帧
  ├─ WebSocket /ws ──► Python 服务器 (aiohttp, server.py)
  │                       ├─ Soniox 实时识别 + 双向翻译（stt-rt，two_way，language_a=对方语言, language_b=我的语言）
  │                       └─ Soniox 实时语音合成 TTS（tts-rt-v2，按目标语言），音频分块回传浏览器用 Web Audio 播放
  └─ HTTP /api/assist /api/summary /api/reminders /api/translate ──► assist.py ──► NewAPI（OpenAI 兼容）
                          快模型 LLM_FAST_MODEL=groq-qwen-27b（建议/清单/追问/打字翻译）
                          纪要模型 LLM_SUMMARY_MODEL=gpt-6-luna（纪要）
                          备用：限流(429)或出错时自动换 LLM_FALLBACK_MODEL（默认 = 纪要模型）重试一次
```

- **页面**：纯静态 HTML/JS/CSS，没有框架。
  - `app.js`：音频、字幕、朗读队列、对坐模式、语言切换。
  - `assist-ui.js`：场合、清单、建议、还没问、纪要、打字。
  - `echo.js`：回声过滤和音量压低。
  - `lang.js`：语言对。
  - `i18n.js`：界面文字词典。
- **服务器 `server.py`**：
  - 处理 WebSocket（音频进，字幕、译文、TTS 出）、`/config`、`/api/*`，以及访问码校验（`ESCUCHA_PASSCODE` 环境变量，空 = 不校验）。
  - 另有 `meta` / `local`(Whisper) / `demo` 三种识别后端；线上用的是 `soniox`。
- **AI 逻辑 `assist.py`**：
  - 拼提示词、解析 JSON、合并清单、过滤"重复追问"、判断告别语、生成纪要，以及 `pair()` 语言对校验。
- **计划改用 Meta 模型**：Meta 额度到账后，
  - 建议/纪要换成 `muse-spark-1.3`，只需改环境变量；
  - 识别可换 `muse-voice-transcribe-1.0`，代码里已有 MetaRelay，需实测；
  - Meta 没有语音合成，朗读继续用 Soniox。
- **部署**：
  - QNAP NAS（Container Station）上的 Docker 容器 `escucha`（端口 18094→8790），前面放一个支持 WebSocket 的 HTTPS 反向代理（`your-domain.example`）。
  - NewAPI 在同一 Docker 网络内（`http://new-api:3000/v1`）。
  - 发布方式：经 Mac mini 把文件 `docker cp` 进容器，Python 改动时重启容器。
  - Mac 上 `~/escucha-deploy/escucha-v7.tgz` 是可重建的完整包，不含 `.env`。
- **隐私**：音频不保存；需要联网（不做离线模式）。

## 3. 功能详情与行为规则

### 3.1 全双工（同时说同时听）
- 麦克风开启时设 `echoCancellation / noiseSuppression / autoGainControl = true`。朗读期间**不关麦**。
- **回声过滤**（`echo.js`）：
  - 记录最近 3 段正在朗读或刚读完的文字。朗读期间以及结束后 **1.5 秒**内，识别结果和朗读内容的词重合率 **≥60%** 时，判为回声。
  - 回声行隐藏（`.echo`），不进入对话记录、建议和纪要。
  - 中、日、韩按字比较，其他文字（拉丁、西里尔、阿拉伯…）按词比较。
- **压低音量（ducking）**：朗读时识别到"不是我的语言"的真实说话（至少 2 个词），朗读音量降到 **30%**；对方安静 **1.5 秒**后恢复 100%。
  - 中间结果按文字系统粗判语言；最终结果按 Soniox 给的语言判断。
- **朗读队列**：一次只读一句。我的话（给对方）和对方的话（给我）**不会重叠**；有 20 秒保险超时。

### 3.2 任意两种语言（17 种）
- 支持的语言：zh es en fr de it pt ar ru ja ko nl pl tr uk vi hi。Soniox 的识别、翻译和朗读都支持这些语言（已对照 TTS 官方语言表）。
- **语言按钮**：在顶部右侧，显示如 `中⇄西` / `EN⇄ES`。点开后有"我的语言"、"对方的语言"和"互换"。
  - 两种语言相同会被拒绝。
  - 选择保存在 localStorage。
  - 收听中切换会自动断开重连。
- 语言对会传给：
  - Soniox 的识别提示和双向翻译；
  - 朗读语言（我的话用对方语言读，对方的话用我的语言读）；
  - 所有 `/api/*` 请求（`me`/`them`）。
  - 服务器 `pair()` 校验，非法时回到 zh/es。
- **哪句是"我说的"**：按 Soniox 判出的语言是否等于"我的语言"来定。
  - 风险：两种语言很像、或夹杂另一种语言时可能判错。

### 3.3 界面跟随"我的语言"
- 所有按钮、面板、占位提示、状态文字、场合名、清单项名、还没问名称、纪要标题和按钮、访问码提示、aria-label 都来自 `i18n/*.json`（每种语言 132+ 个键）。缺的词回落到英语。
- `<html lang>` 跟着变；语言名称用浏览器 `Intl.DisplayNames` 以我的语言显示（中文界面沿用内置中文名）。
- 服务器状态消息带 `key`，前端按我的语言显示。
- AI 生成的内容（清单值、术语解释、建议说明、纪要）由提示词要求用我的语言输出。
- 对坐上半屏的提示文字（Último↓、空白提示）用**对方语言**。

### 3.4 场合（自动判断 + 手动）
- 共 5 个场合：日常 / 看医生 / 学校 / 银行 / 政府办事。手动选择入口在 ⚙︎ 设置里；顶部小标签显示当前场合，点它打开设置。
- **自动判断**：
  - AI 每轮都会判断场合。对话至少 2 句、且用户没有手动选过时，自动切换，并显示"像是在看医生，已切换 · 改"。
  - 点"改"回到原场合；手动选过的场合不会被 AI 覆盖。
- **术语**：对方话里的办事或专业术语，在字幕下方用黄色小条加一句解释（我的语言）。

### 3.5 已知信息小清单
- **项目**：时间、地点、资料、费用、联系人、诊断、药和用量、疗程、复诊、证明、手续费、截止、预约。
- **更新**：每次对方说完一句，AI 根据**整场对话**补充清单。只增不减，空值和"未知"之类不覆盖已有值。
- **每个场合的必问项**：
  - 看医生：诊断、药和用量、疗程、复诊、证明、费用
  - 学校：时间、资料、联系人
  - 银行：手续费、资料、截止
  - 政府：预约、资料、截止
  - 日常：无
- **显示**：屏幕顶部一行可折叠，"已知 N 项：…"。

### 3.6 建议回答
- **触发**：对方每说完一句，译文完成后 150ms（未标完成则 700ms）调用 `/api/assist`。
  - 用整场对话（最近 40 句）+ 当前清单 + 场合。
  - 旧请求的结果如果晚到，会被丢弃。
- **内容**：
  - **2 条**回复：贴合对方最后一句，不一定是是/否；对方语言的句子在下，我的语言的说明在上。
  - **可选第 3 条追问**：只能问"基础项（时间/地点/资料）+ 本场合必问项"里**还空着的**。
  - 代码会再过滤一次：已说清的项（日期时间也算在 time 里）**绝不再问**。
- **显示规则**：默认**隐藏**（屏幕小），只有点了输入框才显示。占位提示写着"打字，或点这里看 N 条建议"。
  - 点一条 → 填进输入框，可以修改后发送。
- 建议只在对方说话后更新；我说话后不更新。

### 3.7 还没问（结束前提醒）
- **触发**：点"结束"；或对方说告别语（多语言：adiós、hasta luego、goodbye、au revoir、auf Wiedersehen、до свидания、再见…）时自动弹出。
- **内容**：本场合必问项里整场都没提到的。
  - 每项显示名称（我的语言）和现成的问句（对方语言）。
  - 对方说西语时直接用内置问句；其他语言由 AI 翻译。
- 点一项 → 作为"我的话"加入对话并**立即朗读**，然后变灰。
- 都问过了 → 显示"该问的都问到了 👍"。
- 面板里还有"继续对话"和"结束并生成纪要"两个按钮。

### 3.8 纪要
- **生成**：纪要模型根据整场对话 + 清单生成。内容是 3–5 句总结（我的语言）、待办（日期/时间可选）、关键词（对方语言词 + 我的语言解释），再附上已知信息。
- **操作**：
  - 待办可勾选；
  - "加入日历"导出 `.ics`，只包含有日期的待办；
  - "复制"复制纯文本纪要。
- **已知问题**：模型有时会编造日期。实测有一次把"周二"写成了今天的日期。

### 3.9 打字输入
- 输入框在底栏上方。输入我的语言 → `/api/translate`（快模型，带对话上下文）→ 显示成"我的话"，并按开关朗读给对方。
- 可以用来：不方便说话、不能说话，或者怕识别错的时候。

### 3.10 两个朗读开关（⚙︎）
- **"朗读我的话给对方"**：默认开。我说话（或打字）、译文完整后朗读对方语言。有 400ms 防抖，一句只读一次。
- **"朗读对方的话给我"**：默认关。打开后用我的语言、**60% 音量**朗读对方的话。
- 可以选声音，有"试听"。声音是 Soniox 的多语言声音，标注性别。

### 3.11 对坐模式（手机平放桌上，两人对坐）
- **分屏**：下半屏朝我；上半屏的每一行单独旋转 180°，朝对方。iOS 不能滚动整体旋转的区域，所以按行旋转；两半都能正常滚动。
- **下半屏（我的视角）**：
  - 对方的话：大字我的语言，下面小字原文。
  - 我的话：小一号蓝色，下面小字对方语言。
- **上半屏（对方视角，v3 起）**：
  - 对方自己的话：**只显示原文一行**，小一号，不再双语。
  - 我的话：大字对方语言，下面小字我的原话，方便我核对。
- **滚动**：两半各自滚动。回看时来新消息不会把页面拉走，会出现"最新 ↓ / Último ↓"按钮（对方那颗是倒着的，用对方语言）。
- **切换**：对坐和普通模式反复切换没有残留；开关状态会记住。
- **样式（v7）**：
  - 上半屏深色，略带蓝色调，和下半屏同一套配色。
  - 中间有一条细渐变分隔线，两侧有语言小标（`ES` 倒向对方，`中` 朝我）。
  - 两半空白时各显示一句提示："Hable, le escucho"（对方语言）和"请说话，翻译会显示在这里"。
- **给对方看**：底栏按钮，全屏白底超大字显示我最近一句的对方语言版本，可以翻转 180°。

### 3.12 无障碍
- **盲人**：两个朗读开关都打开 = 双向语音。所有按钮、开关、面板都有 aria-label；状态行是 `role=status`。开始按钮的读法在"开始收听/停止收听"之间切换，对坐按钮有 `aria-pressed`。
- **聋人**：两个开关都关 = 纯字幕，字号大。
- **不能说话的人**：用打字输入 + 朗读，或者点建议、点"还没问"直接朗读。
- **触控**：底栏 5 个按钮（设置、对坐、开始/停止、给对方、结束），都是统一的 SVG 图标，触控区域至少 44px。
- **未做**：提示音（开始收听、收到新句子等）。

## 3.13 Meta 模型用在哪里（给评委）

| 用途 | Meta 模型 | 怎么用 | 为什么 |
|---|---|---|---|
| 对话纪要（总结+待办+关键词） | `muse-spark-1.3`（Chat Completions，reasoning_effort=minimal） | 结束对话时一次调用，整场对话+清单 → JSON | 实测 P50 1.3 s，比原来的 4–5 s 快；质量好 |
| 打字翻译（不能说话的人） | 已改回快模型 `groq-qwen-27b` | Meta 线上 1.2–2 s，太接近 3 秒超时；快模型线上 0.09–0.14 s | `LLM_TRANSLATE_MODEL=groq-qwen-27b`，想再试 Meta 只改这一行 |
| 说话人区分（谁在说） | `muse-voice-transcribe-1.0` 实时 WebSocket，`DIARIZATION` 模式 | 服务器把同一路麦克风 PCM 并行送 Meta（密钥只在服务器）；只用它的 speaker 事件，按时间重叠给字幕行标 说话人 A/B；语言判不准时按说话人归属我/对方 | 解决"只靠语言判断谁在说"的缺陷；不影响字幕延迟（字幕仍由 Soniox 流式翻译给出），标签约在一句话结束后 1–1.5 s 出现 |
| 建议回答/清单（每句都调用） | 暂不用（实测 P50 2.7–3.2 s，太慢） | 仍用 groq-qwen-27b（0.6 s） | 后续可做"先出快版、Meta 版到了再替换" |

- Meta 转写本身不翻译，且不支持 ru/uk；所以实时字幕和翻译继续用 Soniox，Meta 转写只做说话人区分。选 ru 或 uk 时自动关闭说话人标签。
- 所有 Meta 调用失败都会静默降级：纪要回落 NewAPI；说话人标签不出现，字幕照常。

## 6. 已知问题与限制

1. **阿拉伯语界面没做从右到左（RTL）**，只翻了文字。
2. **长按钮文字会被截断**：部分语言在底栏显示"…"。
3. **15 种语言的界面文字由 AI 翻译**（中、英为人工），只抽查过，需要母语者校对。
4. **非默认语言对的真人语音没测过**：比如 en⇄fr 对着麦克风说话，只做过单元测试和 API 实测。
5. **groq-qwen-27b 偶尔被限流**，会自动换备用模型，但备用模型更慢（约 2 秒）。
6. **容器没有挂载目录**：文件是 `docker cp` 进去的，容器重建就会丢，需要用 `escucha-v7.tgz` 重建镜像或挂载目录。
